\begin{frame}{Mindset Change}
  \textbf{Old (last deck, slides 14--15):}
  \begin{itemize}
    \item Run 5 NN models on mcf; pick the best by validation accuracy.
    \item Single end-to-end IPC number per model.
  \end{itemize}

  \vspace{0.6em}
  \textbf{New (this deck):}
  \begin{itemize}
    \item For each NN family (GRU first; then CNN / RNN / Transformer / Perceptron / NeuTNN), \emph{change one thing at a time}.
    \item Record per-variant accuracy / latency / IPC.
    \item Look for which feature combinations actually help on which workloads.
    \item Insights come from the sweep itself, not from a pre-decided goal.
  \end{itemize}

  \vspace{0.6em}
  \textbf{Why GRU first} (paper-grounded):
  \begin{itemize}\small
    \item Liu, Tziantzioulis, Wentzlaff, MEMSYS 2023 (Princeton): LSTM $\to$ GRU saves $\sim$30\% MAC at equal IPC.
    \item Sequence-capable (unlike Perceptron), simple (unlike Transformer).
    \item d2l.ai chapter on GRU as reference implementation.
  \end{itemize}
\end{frame}

\begin{frame}{Three Methodology Fixes vs.\ Prior Deck}
  \begin{enumerate}
    \item \textbf{Time-split train/val} (first 70\% / last 30\% of the dumped trace, in order). \\
          \emph{Prior:} random 80/20 split $\Rightarrow$ training set saw future accesses (leakage).
    \item \textbf{Cross-trace evaluation.} \\
          Train on one trace (e.g.\ \texttt{605.mcf\_s}); evaluate IPC on a \emph{different} trace (e.g.\ \texttt{620.omnetpp\_s}). Tests generalization, not memorization.
    \item \textbf{(page, offset) dual-head output (Voyager-style).} \\
          \emph{Prior:} only predicted offset within the current page; jumping to a new page guaranteed a wasted prefetch.
  \end{enumerate}

  \vspace{0.6em}
  \textbf{Real evaluation regime:}
  \begin{itemize}\small
    \item ChampSim \textbf{25M warmup + 25M simulation} per run. (Smoke runs were 1M+5M; DPC-3 maximum is 200M+500M $\approx$ 4.5~h per run, infeasible for a 25-cell sweep.)
    \item No truncated CSV loads. Full trace dumps.
  \end{itemize}
\end{frame}

\begin{frame}{The Sweep: 4 GRU Variants}
  \textbf{Each variant adds exactly one feature vs.\ the previous one.}

  \vspace{0.5em}
  \begin{center}
  \footnotesize
  \begin{tabular}{lll}
    \toprule
    \textbf{Variant} & \textbf{Feature added} & \textbf{Question it answers} \\
    \midrule
    V1 & GRU over last 4 quantized deltas (base) & Can a pure sequence model predict next access? \\
    V2 & + per-PC embedding (12-bit hash)         & Does knowing which load helps? \\
    V3 & + page-hash embedding + page head        & Does Voyager's dual-head help? \\
    V4 & + per-PC running miss\_rate, log-freq    & Do hardware counters add signal? \\
    \bottomrule
  \end{tabular}
  \end{center}

  \vspace{0.6em}
  \textbf{Architecture is fixed across variants:}
  \begin{itemize}\small
    \item Embed delta ($257 \to 16$). GRU hidden = 64.
    \item Concat extras $\to$ two linear heads (offset 64-way, page-hash 4096-way).
    \item Cross-entropy loss = offset CE + page CE.
    \item Optimizer: Adam, lr $=2\!\times\!10^{-3}$, 5 epochs, batch 512.
  \end{itemize}
\end{frame}

  \vspace{0.2em}
  \textbf{What V7 tells us (the key number):}
  \begin{itemize}\scriptsize
    \item V7 trains and tests on \emph{the same} workload (mcf, time-split). val\_off = 0.030--0.036 = \textbf{only $2\times$ above chance}. Even with zero cross-binary mismatch, the GRU barely learns.
    \item \textbf{Conclusion: both bottlenecks are real.} Feature set is too weak for pointer-chase (architecture bottleneck). AND PC/page embeddings are binary-specific (generalization bottleneck).

  \end{itemize}

    V4 + PC stats   & 0.2807 & 0.889$\times$ & +0.6\%  & 58\% \\

    \bottomrule
  \end{tabular}
  \end{center}

  \vspace{0.3em}
  \textbf{Insights:}
  \begin{itemize}\scriptsize
    \item \textbf{V1$\to$V2 drops IPC 8\%:} PC embedding memorizes mcf, fires wrong prefetches on omnetpp. \emph{High val accuracy $\Rightarrow$ worse IPC. Confirmed at system level.}
    \item \textbf{V2$\to$V3: IPC flat.} Page head adds no IPC benefit. Page hash is workload-specific.
    \item \textbf{V3$\to$V4: tiny recovery.} pc\_stats as soft regularizer improves slightly, consistent with V5's in-distribution val\_off gain.
    \item \textbf{Trigger rate frozen at 58\%.} All prefetches are emitted with similar (low) confidence. Root cause: the GRU's softmax is near-uniform -- it is not confident about any prediction.
    \item \textbf{V7 upper bound (in-distribution) = 3\%:} Even on mcf itself, model is only 2$\times$ above chance. \emph{The feature set cannot represent pointer-chase patterns, not just cross-trace.}
  \end{itemize}
\end{frame}

\begin{frame}{What the Sweep Is Telling Us -- 3 Ideas}
  \textbf{V7's val\_off = 0.03 (in-distribution, only 2$\times$ chance) is the diagnostic.}
  \emph{The feature set, not just generalization, is the bottleneck.}

  \vspace{0.3em}
  \begin{enumerate}
    \item \textbf{Idea A -- Change the prediction target: predict $\Delta_{n+1}$ (next delta), not offset.}\\
      Current target: "which offset in the current page will the next access land?" -- near-random for pointer-chase. \\
      Proposed: predict the signed delta $\Delta_{n+1} = addr_{n+1} - addr_n$, then compute target as $addr_n + \Delta_{n+1}$. \\
      \emph{Why:} delta is directly conditioned on the delta history by definition. Stride workloads will nail it. And the training signal is not diluted by page-crossing accesses. Hashemi 2018 framed this as the baseline; we can compare GRU vs their LSTM on this exact formulation.

    \vspace{0.2em}
    \item \textbf{Idea B -- Per-PC-bucket mini-GRUs (Voyager's hierarchical trick for cross-trace).}\\
      One global GRU shares parameters across all PCs. PC embedding fails cross-binary. \\
      Proposed: hash PCs to $K = 64$ buckets, train $K$ independent tiny GRUs (hidden=16). Each bucket sees only its own PC's accesses -- no cross-PC noise. Bucket-level generalization relies only on delta patterns, not addresses.

    \vspace{0.2em}
    \item \textbf{Idea C -- Reuse-distance as a feature (hardware counter analog).}\\
      Current pc\_stats = running miss\_rate + log\_freq. These are aggregate statistics. \\
      Proposed: per-access reuse distance = \#accesses since this cache line was last seen. If reuse $> $ LLC size $\approx$ streaming/uncacheable. If reuse $\leq$ 8 $\approx$ hot working set. This feature directly captures \emph{cacheline behavior}, not just PC behavior. Analogous to APT-GET's LBR elapsed-time signal.
  \end{enumerate}
\end{frame}

\begin{frame}{Next: Same Sweep, Other NN Families}
  \footnotesize
  After GRU, repeat the controlled-variable methodology on:
  \begin{center}
  \begin{tabular}{p{2.0cm}p{11.5cm}}
    \toprule
    \textbf{Family} & \textbf{Why next, and what to vary} \\
    \midrule
    Perceptron  & Cheapest hardware. Sweep history depth, hash size, $\mu$arch counter inputs. Reference: Jim\'enez \&\ Lin 2001 hashed perceptron in ChampSim. \\
    CNN         & 1-D conv over delta history. Sweep kernel width 2/3/5 and channel count. \\
    Tiny LSTM   & Same as GRU but with extra cell gate -- check whether GRU's MAC saving is genuinely free. Princeton MEMSYS 2023 reports yes. \\
    Transformer & Sweep $d_{\text{model}}$, number of heads, history window. Reference: Voyager 2021. \\
    NeuTNN      & Last -- spike-timing-based, needs a different toolchain (Smith 2017, CMU NeuTNN 2025). \\
    \bottomrule
  \end{tabular}
  \end{center}

  \vspace{0.5em}
  \textbf{Insight protocol} (same each family):
  \begin{enumerate}\footnotesize
    \item Define base model.
    \item Sweep one input feature at a time (PC, page, counter, phase\ldots).
    \item Record acc / latency / IPC for each variant on cross-trace evaluation.
    \item Annotate every $\pm$ change in the table with a single-sentence hypothesis.
    \item Compare across families: do CNN and GRU rank features the same way?
  \end{enumerate}
\end{frame}
