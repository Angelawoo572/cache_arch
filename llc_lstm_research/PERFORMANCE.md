# How we measure prefetching

- **Accuracy** = used prefetches / sent prefetches. Here a sent prefetch is a new request admitted by the LLC prefetch queue. A timely first use or a late demand merge counts once as used. Include requests still unresolved at ROI end in the sent count and report them separately. In the raw CSV use `prefetch_usefulness_per_issued`. The historical `prefetch_accuracy` field measures accuracy among resolved independent requests and is a diagnostic. [CMU 18-447, slides 17 and 35](https://course.ece.cmu.edu/~ece447/s15/lib/exe/fetch.php?media=onur-447-spring14-lecture27-prefetching-beforelecture.pdf#page=35) · [Feedback-Directed Prefetching §3.1.2](https://users.ece.cmu.edu/~omutlu/pub/TR-HPS-2006-006.pdf#page=8)
- **Coverage** = baseline demand misses served by prefetching / all baseline demand misses. Count each matched NoPF LLC miss once. Report the timely subset separately. The current logs have per-run queue IDs. Until the same demand can be matched across policies, report **net MPKI reduction** = `1 − MPKI_PF / MPKI_NoPF`. Pollution and changes to the lookup stream can affect this number. [CMU 18-447, slide 35](https://course.ece.cmu.edu/~ece447/s15/lib/exe/fetch.php?media=onur-447-spring14-lecture27-prefetching-beforelecture.pdf#page=35)
- **Timeliness** = on-time prefetches / used prefetches. An on-time prefetch fills before demand tag lookup and is still resident when used. A late prefetch is already in the LLC MSHR when a demand merges. Report fill-to-use slack and unused evictions alongside the ratio. Denominators of zero yield an undefined rate. [CMU 18-447, slides 18 and 35](https://course.ece.cmu.edu/~ece447/s15/lib/exe/fetch.php?media=onur-447-spring14-lecture27-prefetching-beforelecture.pdf#page=35)
- **LLC hit rate** = hits / lookups. **Miss rate** = misses / lookups. **MPKI** = `1,000 × misses / retired instructions`. Use completed LLC demand data-load lookups and pool counts before dividing. With total latency on a miss, **AMAT** = `hit rate × hit latency + miss rate × total miss latency`. IPC also depends on overlap and exposed stalls. [CMU 18-447 cache lecture, slide 7](https://course.ece.cmu.edu/~ece447/s15/lib/exe/fetch.php?media=onur-447-spring15-lecture18-caches-afterlecture.pdf#page=7)
- **Execution time** = `instruction count × CPI × clock period` = `cycles / frequency`. **IPC** = retired instructions / cycles. At fixed work per core, **ROI time** = `max(core finish cycles from ROI start) / frequency`. **Speedup** = `T_NoPF / T_PF` and **time saved** = `1 − T_PF / T_NoPF`. Aggregate IPC uses total retired instructions divided by makespan cycles. Keep simulator wall time separate. [CMU 18-447 performance, slide 12](https://users.ece.cmu.edu/~jhoe/course/ece447/S10handouts-jose/L05.pdf#page=12)
- **DRAM traffic ratio** = bytes transferred with PF / bytes transferred with NoPF for the same work. **Bandwidth** = bytes / time. Use demand reads, prefetch reads, and writebacks, and report both fixed-degree and comparable-traffic results. The current Pythia run can include traffic from a core that already reached its individual ROI target. [CMU 18-447, slide 35](https://course.ece.cmu.edu/~ece447/s15/lib/exe/fetch.php?media=onur-447-spring14-lecture27-prefetching-beforelecture.pdf#page=35) · [HW6 prefetching solution](https://course.ece.cmu.edu/~ece447/s15/lib/exe/fetch.php?media=hw6_sol.pdf#page=7)

## Prediction latency and hardware cost

- Compare ingress-to-fill time with trigger-to-target lead time. Measure latency through the predictor and queues, sustained decisions per cycle, same-core state hazards, and dropped predictions. A large line offset only helps when it provides more useful time before demand.
- Charge candidate and tag filtering to the hardware budget. The conventional simulator currently checks LLC tags and queues synchronously. A hardware comparison needs timed accesses or a bounded filter. [DPC4 infrastructure](https://sites.google.com/view/dpc4-2026/submit-work/infrastructure)
- Use Roofline as a throughput bound. For SPEC integer workloads, an instructions-per-DRAM-byte variant gives `IPC ≤ min(compute ceiling in instructions/cycle, sustained DRAM bytes/cycle × instructions/DRAM byte)`. Measure demand latency, outstanding misses, and exposed memory stalls separately. [Roofline](https://escholarship.org/uc/item/5tz795vq)
