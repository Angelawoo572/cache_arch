# 多核共享 LLC 入口的 RNN–LSTM 预取

研究问题是：当各核的 L2 demand-load miss 到达共享 LLC 时，一个足够小、能及时给出候选的 LSTM，能否在有限的 DRAM 流量下减少暴露在执行关键路径上的访存等待？

本地与 Sacramento 都使用 cache 根目录下的 `llc_lstm_research/`，对应 GitHub 的 `experiment/llc-lstm-research` 分支。本轮交付是论文阅读、源码核对和实验设计。后续的采集、模型、配置和结果都放在本目录。

## 放置位置

在共享 LLC 的 demand read queue 入口旁监听各核从 L2 转发的 data LOAD miss。请求照常进入 LLC，LSTM 在旁路更新状态。它预测的行提前从下层取回并填进 LLC。首版只消费成功新入队的请求，合并请求单独计数。当前请求的 LLC hit/miss 在入口还未知，未来的命中结果只用于监督和评估。 [Pythia 源码核对](PYTHIA.md)

```text
各核私有 L2 → data LOAD miss → LLC 读队列 → LLC 查询 → DRAM（如缺失）
                                   │
                                   └→ LSTM → 预取队列 → DRAM → 填入 LLC
```

## 第一版 LSTM

- **输入**。每个 core 维护自己的序列，按该核实际送到 LLC 的事件更新。每步 5 个标量：相邻 cache line 的有符号 delta、与上一次到达的周期差、当前页内行偏移、当前 PC 是否等于上一次 PC、当前事件入队前的共享 LLC MSHR 占用率。地址差和周期差做有界缩放，PC 特征取决于上游是否保留 load PC，采集阶段先核对。共享特征消融把 MSHR 输入置零。当前地址用于计算候选，绝对物理地址不作为神经网络输入。
- **递推**。单层 LSTM，隐藏宽度 8。各核独立保存 `h, c`，共用一份冻结权重。每次到达只更新一次状态。训练按时间顺序分块，先用 16 步截断反传，跨块传递数值状态但截断梯度。运行和训练在 trace 起点或已声明的区段边界重置状态，验证和测试使用自己的预热前缀。
- **输出**。线性层输出 3 个分数，对应同页 `+1`、`+2`、`+4`。每个分数独立估计该候选在有效时间窗内瞄准基线缺失的概率，用 sigmoid 和掩码 BCE 训练。首轮每个触发最多发 1 条，选有效候选中分数最高的，分数低于验证集定下的阈值时不发。发出时重新检查目标是否已在 LLC、已在途或缺少队列空间。
- **成本**。每个事件的四门矩阵和输出层共 440 MAC，另计门函数、逐元素运算、状态读写和候选检查。先测每事件推理时延和持续吞吐，再把正时延、有限队列和服务速率放进模拟。当前 demand 路径不会等待 LSTM。 [性能与硬件成本](PERFORMANCE.md)

## 用什么 label

首选 **从实际 demand 生成的逐候选二元标签**。先运行 LLC NoPF，首轮关闭 L1D/L2 数据预取，所有对照使用相同上层策略。每个触发事件为三个候选分别标注，查询同一次 NoPF 日志中任一 core 对该物理行的第一次后续 demand。多个候选可以同时是正例，三个全为零也合法。保留 reason 和提前量，用于区分命中、过晚和缺少后续访问。预取效果由闭环运行衡量。

| 标签 | 条件 |
| --- | --- |
| `1` | 第一次后续 demand 在参考运行中是 LLC miss，且提前量落在 `[T_min, T_max]`。 |
| `0` | 目标 demand 在参考中 hit、提前量太短，或完整窗口内没有需求。 |
| 不纳入 loss | 跨页、观察不足的区段尾部，或触发时已确定无效的候选。 |

提前量用目标 demand 的 LLC 入口周期减触发周期，作为偏保守的 deadline。`T_min` 从开发段的模型服务时间和请求发出至填充的延迟估计，`T_max` 用开发段的时间窗敏感性试验确定。冻结窗口、阈值和发出预算后再看留出结果。真实填充时延和驻留时间会随竞争改变。离线标签只描述可能覆盖的 miss，实际是否及时、是否挤走有用行由模拟器的请求生命周期和闭环指标回答。

**传统 prefetcher 的 teacher label 有用，适合行为复现或同候选过滤。** 如果训练目标是复制 Next-Line、Stride 或 Best-Offset，可以用其动作做模仿对照。若目标是提高 LLC coverage 和 IPC，主要监督信号用上面的真实未来 demand。传统方法作为系统对照，在同入口、同预取队列和相同请求预算下运行。若 NoPF 正例主要集中在 `+1`，且目标是超过 Next-Line，可固定其 `+1`，用 Next-Line 参考运行的剩余 miss 给额外候选标注。把它作为独立的增量实验，单列额外流量。 [2018、Voyager、Pythia 阅读笔记](PAPERS.md)

## 实验顺序

1. **先验证入口和标签。** Sacramento 用两核各跑一份 602 trace，分开开发段、验证段和留出段。先跑 NoPF 与 LLC Next-Line，核对事件计数、核号、PC、合并、物理行、时钟与首次 demand，统计各候选正例和去重后的可覆盖缺失。双 602 用于验证流程和基本规律。共享信号的结论再用错开相位或混合 workload 检查。
2. **先看候选本身的收益。** 用知道未来标签的理想候选作诊断，同时跑无条件 Next-Line 和用相同候选集合的非递归对照。用验证段调阈值，在相同额外请求预算下比较 precision/recall 和去重的候选覆盖。每个测试段都保留从未用于选参数的区间。
3. **训练并回到模拟器。** 在 Colab 训练小 LSTM，导出冻结权重。Sacramento 比较 NoPF、Next-Line、同候选非递归模型、每核 LSTM、带共享队列信号的 LSTM。分别测理想零时延和正时延，计入推理队列、LLC/DRAM 队列和被抑制的预取。
4. **用性能决定是否继续。** 逐核和合计报告 LLC hit rate、miss rate、MPKI，另报预取 accuracy、timeliness、coverage、DRAM bytes、访存等待、IPC 和固定工作量的完成周期。若 hit rate 提升但运行时间未降，用填充提前量、关键访存停顿、MLP 和带宽分辨原因。Roofline 给吞吐上界，单独检查延迟是否真的被重叠。 [指标口径与 Roofline](PERFORMANCE.md)
