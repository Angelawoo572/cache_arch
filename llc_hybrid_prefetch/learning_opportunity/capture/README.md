# Continuous demand histories

[Measured corpus and source visibility](MEASURED_DATA.md) · [Primary run register](captures.csv) · [External run register](external_captures.csv)

This native writer observes the same admitted LLC data reads as the baseline prefetchers, in simulator callback order. Separate streams retain source loads, private-cache paths, resource snapshots, issued offers and subsequent demand uses. Dynamic operand identity survives out-of-order execution and changes in cache residency across policies.

The primary register covers the nine long windows of the [original study](../../full_workload/intake/views.csv), with NoPF, Stride, Multi-delta and degree-one SPP. Every primary run uses two-core machine geometry, core 0 active, physical placement slot 0, 50M warmup and 200M measured instructions. The two far windows start with the original source-prefix physical-page seed. Warmup trains the conventional state under the inherited demand-only protocol. Capture begins at the measured interval. History initialized from these tables is left-censored at that boundary. The shorter writer fixture has its own [validation table](fixture.csv).

The [expansion experiment](../expansion/README.md) supplies all four conventional outcomes on those same operands. Its continuous Stride file and this richer copy contain the same arrival population. Run `python3 -B "$p/capture/catalog.py" --external` for the validated external inventory.

## Find or read a row

Under either cache root, runs live at `llc_hybrid_prefetch/learning_opportunity/raw/capture/runs/<case>__<policy>/`. The [input registry](../../full_workload/data/trace_files.csv) gives the compressed source recording, decoded input view and placement seed. Each run's `complete.json` records the view, policy, warmup, measured span and source ordinal base. `capture_validation.json` records parity and stream sizes.

Each binary stream contains fixed-width rows of little-endian unsigned 64-bit integers. Every 32,768 rows form an independent gzip member. The matching `<name>.index.csv` gives its starting row, row count, compressed byte offset and compressed byte length. The last member can be shorter. Row indices begin at zero. Standard gzip readers can traverse the full concatenated stream. The [reader](access.py) can seek directly to any member.

| Stream | Columns, in file order | Availability |
|---|---|---|
| `arrival` | operand key, PC, simulated physical line, cycle | LLC demand admission. This includes eventual hits, misses and late uses. File order is the arrival order. |
| `ingress_state` | observer sequence number, packed queue occupancy | Same rows as arrival, sampled in the same callback. Bytes 0–5 are LLC MSHR, read queue, prefetch queue, DRAM read queue, DRAM write queue and LLC write queue. MSHR occupancy measures in-flight cache requests, a proxy for memory concurrency. The DRAM snapshot would require an explicit feedback path in hardware. |
| `source_load` | operand key, core fetch cycle | All active source-load operands at the traced instruction reader. Use the key to index the original 64-byte record for PC, virtual address, branch flags and source/destination registers. These core-side fields need transport to become LLC-visible. |
| `cache` | observer sequence number, operand key, cycle, physical line, event code | Every instrumented demand-data callback at L1D, L2 or LLC, except LLC admission, which has its own stream. Queue retries and merges can produce multiple rows for one operand. An absent tag lookup is distinct from a hit. |
| `offer` | observer sequence number, trigger operand key, request ID, target physical line, cycle, event/reason codes, consumer operand key | Each native decision, including silent steps, rejection, dispatch, fill and first use. Request ID links the lifecycle. Zero consumer denotes no demand operand at that callback. A timely or late use is a retrospective label until its callback occurs. NoPF has no proposal rows. |
| `head_wait` | operand key, retire cycle, observed ROB-head wait cycles | Positive waits only. A missing row for a measured source load means zero qualifying cycles under this diagnostic. Feedback is complete at retirement. Overlapping waits must not be counted as additive execution savings. |
| `prefetch_victim` | request ID, victim physical line, incoming physical line, cycle | A tracked prefetch fill evicted a valid line. The eviction alone does not establish pollution or marginal slowdown. |

All binary filenames end in `.u64le.gz`. In these solo runs the core ID is 0. The key is `(absolute one-based source instruction ordinal << 2) | operand` with operand 0–3. The physical line is a 64-byte cache-line number. Its 4 KiB page and line offset are `line >> 6` and `line & 63`. For region-relative analysis, specify the region size separately. Use the recorded page map to translate a known virtual line for an offline join. The source-record fetch order or final VPN map cannot provide information about unknown future pages to the predictor.

Decode `cache.code` as `level = code & 255`, `hit = ((code >> 8) & 255) - 1`, `event = code >> 16`. Levels are 1, 2 and 3 for L1D, L2 and LLC. Hit is 1 for a tag hit, 0 for a tag miss and −1 for other events. Decode `offer.code` as `stage = code >> 32`, `reason = code & 0xffffffff`. Stage and reason IDs resolve via that run's `symbols.csv`. Interpret a silent step's zero target as an abstention. Offer and reason histories expose decisions already made. The capture omits internal confidence-counter values, private SPP signatures and exact warmup-end table contents. Using the current offer as an input would require an explicit hardware path from the conventional predictor after it has made that decision.

Use the shared sequence number to order cache, arrival and offer callbacks that occur in the same cycle within a run. Source fetches, head waits and victim records have cycles but lack that common sequence number. Require a strictly earlier cycle before using them as history alongside an LLC trigger. Conventional runs have separate clocks and different LLC-visible streams. Join by operand key across arms. When a baseline operand never reaches the LLC in another arm, retain that outcome explicitly.

The four-bit-per-operand retirement masks are inherited from the native study. A bit value of 1 denotes an LLC tag hit, 2 a tag miss, 4 a late first-use merge, and 8 a timely first use. The bits combine within an operand. The remaining bit patterns include absent tag observations. The `outcomes_core0.u16le.gz` file stores one word per measured *instruction*, also for instructions without a load. [Mask implementation](../../full_workload/native/observations.inc)

## One demand, two clocks

In MCF-472B, Stride arrival row 226 saw PC `0x402dc0` access physical line `0x32ee6` at cycle 28,557,825. At that callback the predictor proposed the preceding line `0x32ee5`. Request 227 was accepted immediately and dispatched 20 cycles later. The actual load of that line reached the LLC at cycle 28,557,897 (row 229). Its lookup merged with the outstanding prefetch at 28,557,917. The line filled at 28,558,035. The address prediction was correct, but the 72 cycles between the proposal and demand admission yielded a late first use.

The same target was source instruction 50,001,462, operand 0, key 200,005,848. Its NoPF retirement mask was 2 (tag miss); its Stride mask was 6 (tag miss plus late merge). Matching those keys avoids comparing absolute clocks between runs. Within the Stride run, the demand admission and the later lookup have different timestamps. The observed 138 cycles between demand admission and fill describe the realized request. They do not determine what an earlier issue would save under changed queue contention.

## Reproduce and validate

From the cache root, after [preparing the trace views](../../full_workload/intake/README.md) and [building the original native simulator](../../full_workload/native/README.md), run:

```sh
p=llc_hybrid_prefetch/learning_opportunity
python3 -B "$p/capture/build.py"
python3 -B "$p/capture/run.py" --jobs 8
python3 -B "$p/capture/audit.py" "$p/raw/capture/runs/bfs_discovery__stride"
```

Apply `audit.py` to each completed primary folder, then run `python3 -B "$p/capture/catalog.py"` to publish the [complete capture inventory](captures.csv). It requires NumPy, compares cycles, phase counters, raw statistics, page assignments and every operand mask with the unmodified baseline, and inflates every indexed member with CRC validation. It reconciles complete LLC arrivals, source-load totals, L2/LLC tag outcomes and candidate lifecycles with the simulator counters. For three rows in each arrival member, including the two edges, it independently checks the PC and simulated physical line against the original source operand. The `capture_validation.json` file is installed only after these checks pass.

For sequential history, keep a stream's state across compression blocks. Each block boundary is a storage boundary. At a chronological train/development/test boundary, purge target horizons that reach across the split. A request is eligible for issue only after its generating history was available in that arm. Comparing a hindsight target with a legal earlier line or checking an optimistic service allowance measures opportunity. It cannot establish predictive accuracy, timely fills or a causal performance gain.

To read the 64 LLC observations ending exactly at a specified trigger, run `python3 -B "$p/capture/history.py" "$p/raw/capture/runs/bfs_discovery__stride" 10000 --length 64`. It returns ordered PCs, physical lines, page offsets, adjacent and same-PC signed deltas, cycle gaps and pressure at admission. Empty deltas mean the required earlier event was outside this supplied window. For core-side control or register ablations, `source_records` in `access.py` joins the original 64-byte trace by key. Treat unavailable physical dependencies, memory values and future control flow as unknown.

The placement supplement runs the same MCF-472B source prefix under Stride twice (50M warmup and 2M measured). It reverses the six-bit first-touch page index *inside* each allocation chunk in one run, matching the earlier [physical replay control](../../opportunity_study/physical_replay/build.py). This preserves VA, PC, line offset, capacity and page uniqueness, while potentially changing set/bank conflicts and LLC event order. `python3 -B "$p/capture/placement.py"` builds the independent allocator, checks every matched virtual page and verifies all 608,699 source operand keys in trace order. [Placement measurements](placement.csv) The two complete raw folders are `mcf17_layout_original__stride` and `mcf17_layout_reversed__stride` under the same capture root. These diagnostics form a separate population from the 200M windows.

The [source audit](source_parity.py) reads each original 64-byte instruction record in the measured interval. It expands all nonzero load operands and compares their full ordered keys, operand by operand, with each of the four captured program streams. Run `python3 -B "$p/capture/source_parity.py"` to repeat the check. Its summary records one population per source view. With `--external`, it checks every source operand and every admitted Stride line against its original PC, virtual operand and simulated page placement in all eleven external captures.

Each host runs its own native audit. For cross-host comparison, `replica.py` records each decompressed member's validated length and gzip CRC, the full retirement mask in 4 MiB blocks, the simulator totals, and the event dictionary. This permits an independent Linux replay to be compared with a Mac replay even when gzip compression differs. The [replica comparison](replicas.py) checks those records and lists the verified row counts. Some Linux copies come from an independent run. Others use the [lossless transfer utility](transport.py) to reconstruct the original indexed gzip tables. The provenance column identifies each method. Each is matched to that host’s native counters, timing, page map and full retirement mask. A reconstructed copy also inflates every gzip member sequentially against the original source-verified certificate. This reuses the source lookup and lifecycle counts once all observation rows, event definitions and native outcomes match. Use `audit.py --full-source` to repeat the source lookups on the receiving host. A 250K-instruction BFS/SPP fixture matched across hosts in 151,395 observer rows and all 250,000 retirement words.

To compare a fresh pair directly, run `python3 -B "$p/capture/replica.py" "$folder"` after the native audit on each host. Copy one `replica_blocks.json` to the other host and pass its path to `--compare` on the same command. For the full report, keep certificates under `raw/capture/verified_hosts/{mac,sacramento}/<case>__<policy>.json` and run `replicas.py`. First run `replicas.py --record-origins` on Sacramento and copy its certificate directory. It reads the run command preserved in each completed capture to distinguish native replays from transferred copies. Repeat with `--external` for the external panel under `external_verified_hosts`.

One callback has a host-dependent presentation order. After fixed-work retirement, `hybrid_finish` walks an unordered map of outstanding prefetches and emits their `unresolved` records at one shutdown cycle. In the BFS-3 later window, Stride had 552 such rows, and Multi-delta had 1,298. Linux and Mac enumerated some request IDs in different orders. Both raw files preserve their native order. Exclude all shutdown inventory from predictor history.

For replica checks, every row through the last live callback retains its original order. The certificate requires a contiguous terminal suffix at one cycle, one row per unique request ID and no demand consumer. It compares the full trigger, target, ID, cycle and reason after sorting that suffix by request ID. The [replica table](replicas.csv) reports ordered rows, post-run inventory rows and shutdown cycle separately. Demand ordering, retirement outcomes and future-label joins have no such exception.
