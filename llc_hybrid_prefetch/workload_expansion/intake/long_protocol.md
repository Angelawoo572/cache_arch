# Deeper Google discovery windows

After the short Google windows showed sparse repeated contexts, keep exactly the same seven Google discovery objects and extend each object's input to 5,001,024 complete records. This follow-up measures support sensitivity and phase stability on the discovery roster. Use every previously registered Google discovery case, without selecting on comparative performance or particular learned rules. The six named test objects and their reserved families stay unopened.

For the native experiment skip 2,000,000 original instructions, warm for 1,000,000 and measure [3,000,000, 5,000,000). The additional 1,024 records are read-ahead guard. Save each extended trace to its own raw/intake/long directory, then confirm its first 801,024 records are byte-identical to the input used for the shorter windows. The long-run interval is disjoint from both original ROIs but shares the recording, application label and possible phases with them.

All seven extended objects were acquired. The HTTP-range stage received 115 MiB compressed; it validated each range against the corresponding manifest length and published each output after confirming its entire 801,024-record short prefix byte-for-byte. Independent and native readers agree on all seven new 2M-instruction ROI counts. The deep windows contain 429,697–516,754 source-memory operands per recording. The global checks also cover 35,007,168 complete records across the seven extended inputs.
