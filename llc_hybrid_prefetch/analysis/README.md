# Reading the paired measurements

Run `python3 analysis/characterize.py` from the study directory after the simulator has written `complete.json` for both arms. It accepts uncompressed CSV and gzip CSV. Individual pairs can run concurrently with `--case CASE --pair-only`. After all pair jobs finish, use `--combine-only` to publish the small CSV files under `results/`. Cached pair summaries live with the raw files. Recompute a pair with `--refresh` whenever one of its simulation arms changes. `python3 analysis/test_characterize.py` checks dynamic-identity validation and a known prefetch first use.

## Denominators

- **Execution.** A core row covers its registered fixed number of instructions. Speedup divides NoPF cycles by Stride cycles for the same trace and active cores. The mix table uses the last core to retire its measured work as the end of the run. Co-run slowdown divides co-run cycles by solo cycles for that program, region and policy. Weighted speedup sums solo cycles divided by co-run cycles across matching cores. Empty cells indicate unavailable controls or a zero denominator.
- **Alignment.** Each core must have precisely identical ordered instruction/operand, PC and virtual line arrays in both arms. Multiple loads on the same line remain distinct. Each independently resolved LLC lookup is also checked against its own run's canonical demand. All NoPF LLC misses and all Stride LLC misses must reconcile to mutually exclusive paired outcomes. Upstream hits, request-queue merges and forwards can leave a load without its own LLC lookup. A demand that checks the LLC tags and then merges in an MSHR is counted as a tag miss.
- **Coverage.** Paired coverage counts NoPF LLC misses with a Stride LLC hit. Direct timely coverage additionally requires a tracked prefetch first use for the same dynamic load. Direct eventual coverage adds demand merges into in-flight prefetches. Net miss reduction includes both newly introduced misses and avoided misses. All four divide by all NoPF completed LLC tag misses. Inspect the integer numerators and denominators in `core_performance.csv`.
- **Precisions and timing.** Accepted accuracy divides timely plus late first uses by accepted prefetches. Timely accuracy counts only timely first uses in its numerator. Timeliness divides timely first uses by timely plus late first uses. Dispatched, filled, rejected and unresolved requests have separate counts. Average degree divides proposals by Stride ingress decisions, including silent decisions. Fill-to-demand slack and outstanding-demand-to-fill delay are reported only when both timestamps are known.
- **Failure evidence and traffic.** On a persistent miss, an exact merge into an outstanding prefetch is credited first. Otherwise, the report gives the last recorded action for the target physical line strictly before lookup, since that core's previous lookup of the line (or since measured events began). A recent rejection does not establish that accepting the request would have improved execution. A silent trigger exposes its recorded tracker reason. The `traffic.csv` byte counters come from completed DRAM transfers in the measured interval. Pressure sums divided by `pressure_cycles` give time-weighted shared-bank occupancy. Lookup-sampled occupancy is in `pressure.csv`.
- **Head wait.** The main core counters count unique cycles with an in-flight load at the retirement head. Cohort and per-operand totals count a cycle once for each affected operand. Where one instruction has two unresolved loads, their summed waits can exceed the number of unique stalled cycles. The measured completion-time difference is the performance outcome.

## How to read a neighborhood

- In `hit_context.csv`, each eligible NoPF miss → Stride hit is matched to the nearest unused NoPF miss → Stride miss on the same core, trace, target PC and virtual page-offset quartile (16 lines). Matching uses instruction distance, with earlier ID as tie-break and a maximum separation of 65,536 dynamic instructions. A control is used at most once. Report both the number of matched pairs and the number of observations remaining at each offset. Differences describe these matched groups and do not establish which features predict an unseen region.
- Offsets count earlier or later Stride LLC tag lookups **on that core**. The current demand anchors both groups. A negative offset still may occur after the prefetch decision. Same-cycle earlier reads are excluded from the negative offsets. Relative age, page match, PC match and tag hits refer to the named neighbor. The near-line fraction uses distance in virtual cache lines for trace interpretation. Across pages, closeness in virtual space does not establish a close physical target available to an LLC predictor. The future neighbors are retrospective outcomes.
- `examples.csv` links real instructions to candidate IDs, physical lines, and cycles. For each scope it shows an attributable timely first use, an attributable late merge and a persistent miss, where present. A `visible_before_trigger` row strictly predates generation. Demand-relative neighbors have their own availability labels. Stage records describe simulator order when timestamps tie. The physical candidate base/target is in line units. A virtual line in a demand row comes from that load's canonical trace address.

Published summaries keep region and core identities. A synthetic boundary label and a page-offset pattern inferred in SPEC carry different evidence.
