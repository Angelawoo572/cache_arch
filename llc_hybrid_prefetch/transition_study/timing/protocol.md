# When is the last hit already too late?

Before examining this study's new transition counts, fix four solo/co-run comparisons: early GAP BFS-8 with LBM, its LBM peer with BFS-8, MCF 665B with CactuBSSN and LBM 4268B with Xalancbmk. Match the same recording, measured instructions, placement slot and load operand across environments. The four original baseline workload pairs are archived. This separate diagnostic asks whether the *same* timely → late boundary could arise from a different service deadline even when Stride selects the same target from the same trigger.

- Examine actual LLC ingress order on the core, within each PC, within each 4 KiB physical page and within each 64 KiB physical region. Retain every admitted demand in its projection. A timely label requires a paired NoPF miss and a credited Stride first-use hit. A late label requires a paired NoPF miss, a Stride miss and a credited first merge. Other accesses break the run. Count maximal runs of at least two direct timely labels immediately followed by one of those late labels. Distinct projections deliberately overlap. The companion experiment also follows persistent misses, ordinary hits and demand operations that never reach the LLC.
- At each first late load record the last timely access's ingress and completed lookup. Check whether Stride had already proposed the exact target before the preceding timely hit's tag result was visible. On the late arm compute a diagnostic latest issue as its own merge cycle minus its own observed proposal-to-fill interval. Count endpoints where this timestamp precedes that tag result. This is a hindsight comparison under unchanged service delay; alternative issue time can change DRAM scheduling and service. Accept equality in neither strict-before count.
- Look up that late request in the other environment using both dynamic producer and consumer IDs and the physical line. Report missing matches and changed triggers independently. For a matched timely→late request, decompose signed fill slack into proposal-to-consumer-event lead, proposal-to-dispatch and dispatch-to-fill. The consumer event is the first hit lookup or the first merge respectively. Also compare lead to *ingress*, a common event in both arms. All duration comparisons use each arm's own clock.
- Record what held in the previous *two* access positions separately from what held for the same matched target; a matching target does not imply matching neighboring order. Report direction, cohort denominators and first deterministic examples. This is a passive paired diagnosis, not a scheduler intervention or a predictor.
