# Fixed protocol for replaying a transition through the shared LLC

Registered before opening the episode results. This is a diagnostic for the loss of timely coverage after a run of correct Stride prefetches. Previous whole-region A–C measurements, including the lookahead-2 ablation, were already known. This is a new within-episode assessment on existing recordings and a new causal policy comparison.

- Fix the panels to MCF+CactuBSSN region 1, solo MCF region 2, solo LBM region 1, LBM+Xalancbmk region 1, BFS-3 later, BFS-8 early alone and with LBM, alternating 2- and 5-length rows, three-stream shared-PC and separate-PC controls, and compiled rows. Include zero-support and negative cases. The identity list and sample sizes must come from the original NoPF/Stride recordings before scoring a modified run.
- Use the existing demand-only LLC ingress and the native single-degree, same-page shared issuer. Identical geometry, physical map, active core slots, retirement limits, trace order and warmup. Retire all measured work. Native Stride is the reference. The distance-two control always changes a recognized native delta to twice that delta. It keeps the normal rejection at page edges. All mechanisms have the same maximum one issue per admitted anchor. Publish achieved traffic and acceptance since this limit alone does not match actual counts.
- In the **paced-distance** control a direct-mapped 64-entry per-core table holds each PC's previous line, event cycle, last nonzero stride and capped equal-delta run length. Increase distance from one to two only when at least four identical nonzero deltas have accumulated, the immediately preceding and current same-PC ingress are at most 128 cycles apart, and LLC MSHR and DRAM read-queue occupancy are both below 16. Native Stride must have recognized the current delta. If the farther line crosses a 4 KiB page, retain distance one. The 128-cycle threshold is a fixed sensitivity point chosen before examining episode outcomes.
- In **repeated-turn**, a separate run-length register at the same PC remembers the signed repeating stride, completed run length, and departure jump for runs of three or more. After two observations of the same triple, and while at most two iterations before its recorded ending, try the first line after that run. Require the same page. Otherwise use the paced-distance rule. This adds a conventional counterfactual about row boundaries while retaining a native path on other anchors. Both new policies use only current/past admitted physical lines, PC and cycle, plus currently observed queue pressure. Warm the histories during native warmup. Neither rule reads paired outcomes, run-ending labels, target IDs, future service or eventual ROB waits.
- Report complete-run cycles for each program, makespan, traffic, accepted and claimed requests, and observed pollution associations where possible. Assess policy arms on fixed ordered-episode identities, especially first late/persistent failure, previous last timely, and following recovery. Keep projections separate and publish unique dynamic counts to prevent eightfold counting. A lower per-target wait or an additional hit is not a sum of saved whole-program cycles.
- Test exact no-op reproduction against every archived Stride arm. Validate positive-log per-request decisions against a separate prefix-only calculation using the snapshot of the relevant PC entry; carry out a future-suffix perturbation test on the policy update as an additional causal check. Record the evidence for covered and uncovered dynamic demands. The implementation can change for correctness; after registration the rules and thresholds are frozen.
