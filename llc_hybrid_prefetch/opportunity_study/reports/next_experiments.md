# Which experiment would justify learning what to remember?

The first decision is whether a bounded **page-indexed memory** retains the earlier evidence a predictor needs at LLC ingress. Later BFS-3 provides a real positive address-prediction case; BFS-8 supplies a low-support transfer, and CactuBSSN supplies an execution-time case in which finite page recognition can remove most of the benefit. The two verified BFS-3 targets (page offsets 50→51→55 and 9→10→12) are discovery cases. Freeze the contextual rule, report all triggers including false positives, and count analogous events and direct first-use credit in previously untouched regions. Keep both positives and negatives. These are proposed experiments, in priority order. The counts and engineering budgets below describe experimental choices for discussion.

| Priority and question | Matched experiment and falsifier | Result that would change the research direction |
|---|---|---|
| 1. What needs to survive between visits to a page? | Pre-register additional fixed graph and sparse/indirect trace regions before measuring them. On identical triggers compare current context, previous global event, last offset on the current physical page, last offset of an unrelated page matched in age, and a page-local two-delta history. Hold table bytes, issue opportunities, candidate menu and prefetch latency constant. Report event-age strata, unseen-page/key rates, matched newly timely loads, DRAM and each core's fixed-work time against strong conventional controls. Repeat under at least two independently specified physical placements. | If a bounded page-local offset repeatedly explains the gain, use it as the conventional component. A learned retrieval score merits a test only if there are recurring mistakes under the simple rule and a distinguishable alternative cue is already visible early. |
| 2. Is it the **write decision**, replacement, or the physical address vocabulary? | In CactuBSSN compare a compact *tagged physical-page pair* and region-relative offset against fixed +128, adaptive per-PC best offset and a matched-size temporal table. Separately sweep page-handle depth and compare LRU, sampled reuse, and Triage-style utility-aware metadata replacement. Keep the action rank fixed while varying retention, then hold page handles fixed while varying ranking. Charge tag/ownership checks, capacity, metadata lookups and SRAM reads. Count requests whose only blocker was forgotten region identity and the performance actually recovered. | If simple page-pair/reuse sampling survives relocation and captures the savings, a learned memory is unnecessary. A relationship that is useful across nonidentical contexts and consistently lost by reuse, age and confidence policies would motivate learning which writes to preserve. |
| 3. Does a strong temporal organization already solve either problem? | Compare a faithful Triangel/Tetrahedrangel reference or validated port, preserving its native observation stream first. Then adapt it to the same LLC trigger and resource budget and charge LLC ways/ports, coalesced metadata traffic, lookup queues and issue latency. Compare PC-local training with a global trainer. Include SPP and multi-delta. | A loss that disappears with a less filtered observation point motivates moving or forwarding the cue. A loss due to output reach motivates a generator. Losses in cue selection or retention that persist against equal-cost controls would justify a learned-memory test. [Triangel](https://arxiv.org/abs/2406.10627) · [Tetrahedrangel](https://doi.org/10.1145/3821213) |
| 4. Which learning experiment is minimal? | With a fixed legal menu and finite record store, independently ablate write selection and read selection. Compare 2-bit usefulness / age / rarity, a counted linear score and then a small learned score. For read similarity compare exact tag, Hamming distance and one projected key. Train on one set of recordings, select capacity/threshold on a separate development set, reserve untouched regions for native test. Include an ordered vs shuffled control and a fixed convolutional/MLP baseline only where cue order matters. | If only retrieval matters, keep writes conventional. If sparse writes dominate, test a learned write gate before adding attention. If no finite representation improves execution at matched cost, stop model development. |
| 5. Would an auxiliary predictor reach its deadline and help the other core? | Give native Stride a fast path. Modeled auxiliary service must include initiation interval, bounded queue, dropped/stale responses, page revalidation and arbitration. Pair contention-heavy phases and track critical vs noncritical requests and victim attribution. Construct matched interventions with actual service, include null/slower outcomes. | Require stable benefit on the predeclared held-out mixes and at a plausible latency/throughput point. Measure cycle gain per added KiB, metadata access and DRAM byte. Synthesis and an SRAM/energy model are required before a hardware feasibility claim. |

Illustrative storage figures below are logical payload estimates. They exclude ports, control and physical implementation unless individually specified.

**Current design decision.** Keep the choice of model open. The first architecture discussion should decide which finite page identity, state-update rule, observation point and metadata budget to test. Only after those choices survive matched native baselines does it make sense to choose between a small associative table, a learned write gate, recurrence or attention.
