# Workload evidence

- The initial registration covers 18 generated controls, one compiled C program and five real-workload configurations. A separate follow-up adds five generated controls and two later BFS slices. All 31 cases completed under both policies, for 62 executions. Each comparison replays the same source instructions with identical physical page placement. We joined the complete ordered load streams by core, instruction occurrence and operand, then checked PC and virtual line on both sides. The core program may issue many loads that never reach the LLC. [Initial registration](PREREGISTRATION.md) · [Follow-up registration](FOLLOWUP.md) · [Exact case settings](cases.json)
- A **direct timely conversion** is a dynamic demand that missed the LLC with NoPF, hit the LLC under Stride, and personally claimed first use of a line that Stride filled in time. A matched miss-to-hit without that last condition can reflect a residency change. A demand merging with an outstanding prefetch is late. Cycle counts cover fixed retired work. For a two-program run, elapsed time is the larger of the two per-core times. [Outcomes by source event](outcomes.csv) · [Execution time, traffic and pressure](performance.csv)

## Which patterns survived the controls?

| Comparison | Measured outcome | Architectural interpretation |
|---|---|---|
| Alternating 8/24-line rows, unchanged addresses and load count | Stride converted 3,584/8,192 misses in the tight one-chain case and 6,656/8,192 with 192 additional dependent integer operations per load. All 512 row starts missed in each case. Fixed-work speedups were 1.659× and 1.125×. | Spacing improved timeliness. The additional arithmetic also increased total execution time, so the higher coverage yielded the smaller percentage speedup. The tight control in this study serializes loads on the same register chain. |
| Row schedules with longer history | Stride missed all 511 starts of the five-length schedule and all 547 starts of the previous-length paired schedule. It also missed all 544 starts when each row length was redrawn. | A boundary label alone cannot tell which failures are learnable. The previous row length predicts the span of the second row in each repeated pair. The random-row control shares the inadequate last-stride rule without that information. |
| Two interleaved streams | All 8,192 loads reached the LLC. With a shared load PC, Stride supplied zero direct timely conversions. With a separate PC per stream it supplied 7,808. NoPF took exactly 3,247,044 cycles in both. | A simple way of separating streams explains this difference. The static load PCs share an instruction-cache line and page in the generator. |
| Nonadjacent PC cue | Stride missed all 2,048 designated targets in each variant. On the later half, a table fit on the earlier half predicted 1,024/1,024 deltas from the cue PC. Masking only that PC dropped it to 518/1,024. A different demand separated each cue and target. | All held-out cues were observable at LLC ingress. Median lead was 889 cycles, above the training half’s 70-cycle 90th-percentile demand service time. This diagnostic knows which accesses play cue and target roles. It measures available information. An integrated prefetcher would also have to discover those roles, win issue resources and change runtime. [Cue measurements](cue_visibility.csv) |
| Phase changes and recurring noise | Stride converted 128/256 phase-start misses. It converted zero of 6,144 designated irregular motif misses with interleaved noise. | One phase entry still lies on the previous stride within the same page. The other crosses the page. A source-level phase change does not imply a failed address prediction. |
| Page boundary | Identical row-delta sequences had 256 marked second-row starts each. All missed Stride when the start stayed in its page and when a 32-line displacement made it cross. | A same-page failure leaves room for an earlier legal issue. The base policy cannot issue an ordinary prefetch across the other boundary. |
| Memory-level parallelism | With eight integer steps and one dependence chain, Stride converted 8,029/8,192 misses and had 31 late merges. Four independent chains at the same PCs and addresses yielded 1,759 conversions and 6,147 late merges. NoPF mean LLC MSHR occupancy rose from 0.474 to 1.709. | Overlap and lead time changed with the dependency graph. A list of future addresses alone cannot explain the difference. |
| Working set | All 196,608 measured 256 KiB working-set loads disappeared before LLC ingress. The 8 MiB case delivered 196,608 LLC ingress events, 106,545 NoPF LLC misses and 18,646 direct conversions. | A pattern that is clear at the source can be unobservable and unnecessary at the shared LLC. |

## Follow-up tests of longer context

- **Multi-level row pitch.** Within each slab, rows used four lengths and pitches. Gaps between bands varied with slab parity. Stride supplied 6,622 direct conversions among 8,192 measured loads. All 384 subrow starts, 85 band starts and 43 slab starts remained misses. Of the subrow starts, 160 stayed on the current page and 224 crossed it. Every observed band and slab entry crossed a page, so testing higher-level prediction also requires a valid way to address the next page. [Page-conditioned outcomes](boundary_pages.csv)
- **Three streams that change order.** Each stream advanced by a different stride. Its scheduling order changed every 48 loads. A single shared PC yielded zero direct conversions out of 8,192 misses. A separate load PC for each stream yielded 7,503, including 128 out of 171 marked switches. Both NoPF runs took exactly 3,371,516 cycles. Static stream identity enabled a simple rule even when the scheduling order changed.
- **Two nonadjacent cues.** Two earlier PCs jointly determined whether a later target appeared at offset 8 or 40 from the trial base. Two distractor events with a fixed PC immediately preceded the target. Stride missed all 1,024 designated targets. On the untouched later 512 trials, fitting the most frequent offset on the first 512 gave 238 correct with neither cue, 252 with the first alone, 266 with the second alone, and 512 with both in a four-entry table. Masking only the first PC reduced the joint result to 266/512. Median lead from the second cue was 1,170 cycles. This controlled construction demonstrates why joint context can matter and provides a cheap rule to beat. [Joint-cue diagnostic](joint_cues.csv)

## A compiled nested loop

- Clang compiled the C function to 124 bytes of x86-64 code. Unicorn executed those instructions. Each recorded PC, taken branch and data operand came from that execution. Capstone supplied architectural source and destination registers, normalized to the simulator’s x86 register conventions. A native build returned the same 64-bit value. The emulator observed exactly the 3,072 data-array loads derived independently from the 192 C rows. The retirement model replays the static instruction dependencies. Emulator wall time does not enter the measurements. [C source](compiled_rows.c) · [Recorder](record_compiled.py)
- The measured 160,000 instructions contained 1,188 data-array loads. Stride directly converted 964 misses. All 74 measured row starts remained LLC misses. Fixed execution time fell from 384,037 to 314,037 cycles. The C dependency chain accumulates loaded values while the next row address is computed separately. This supplies a compiled positive control. Prevalence in applications requires independently validated labels.

## What did the real recordings show?

| Workload | NoPF misses | Direct timely conversions | NoPF → Stride cycles |
|---|---:|---:|---:|
| GAP BFS-3, solo | 25,393 | 23,949 | 7,997,112 → 6,097,058 |
| GAP BFS-8, solo, held-out recording | 25,372 | 23,912 | 7,949,289 → 6,059,584 |
| BFS-8 with LBM, BFS core | 25,372 | 18,128 | 9,371,187 → 7,004,637 |
| LBM-3766 with BFS-8, LBM core | 10,693 | 4,731 | 2,933,663 → 2,832,277 |
| LBM-3766, same placement, solo | 10,693 | 4,747 | 2,456,509 → 2,060,298 |
| BFS-3, fixed follow-up at 50M–52M | 47,888 | 15,765 | 15,514,952 → 13,798,947 |
| BFS-8, same fixed later position | 854 | 366 | 1,490,183 → 1,429,898 |
| MCF-994, fresh adjacent interval | 26,712 | 237 | 15,015,185 → 14,977,677 |

- **The early BFS phases were streams.** One static PC generated every LLC trigger in each solo recording. Of 25,372 within-PC physical line deltas in BFS-8, 25,169 were +1. The two recordings independently show strong conventional coverage in these short prefixes. The public metadata identifies the benchmark. The correspondence to a named application phase or input graph is unverified. [Measured ingress distribution](real_ingress.csv) · [GAP Benchmark Suite](https://github.com/sbeamer/gapbs)
- **The two later BFS phases diverged.** We registered the same 50M–52M interval for both recordings before examining additional offsets. BFS-3 now showed eight LLC trigger PCs. Only 24,502 of 58,699 within-PC deltas were +1. Stride covered 32.9% of original misses directly. BFS-8 showed six PCs but only 854 ingress events in 2M instructions. Of its 848 within-PC deltas, 840 were +1. It had 366 direct timely conversions and 452 late merges. The later slices identify one mixed-access region and one sparse LLC stream within recordings that looked nearly identical early on. [Later-window registration](FOLLOWUP.md) · [Ingress counts](real_ingress.csv)
- **Shared pressure changed timeliness.** Late Stride merges on the BFS core rose from 656 alone to 6,440 with LBM. The BFS core kept the same input loads, physical placement, 25,373 triggers and dominant delta counts. Stride’s total DRAM traffic for both programs together was 7,248,192 bytes versus 6,524,416 under NoPF. The mixed fixed-work time improved 1.338× over its own NoPF execution. BFS nevertheless finished later than when it ran alone.
- **MCF changed across adjacent regions.** For the same MCF-994 trace, instructions 10,000,001–15,000,000 had 80,320 original LLC misses, 424 miss-to-hit transitions and 110 directly claimed first uses. Instructions 15,000,001–20,000,000 had 26,712 original misses, 291 miss-to-hit transitions and 237 directly claimed first uses. The earlier and later relative cycle reductions were about 0.24% and 0.25%. The mix of missed addresses and the amount of uncovered latency can differ without a substantial change in speedup. [Earlier interval](../../results/core_performance.csv) · [Adjacent interval](outcomes.csv)
- BFS-3 and BFS-8 each use the first 1M instructions to warm and the next 2M to measure. LBM uses identical input positions solo and in the mix, with the same physical placement slot. The adjacent MCF run skips 5M instructions while registering pages, warms on the next 10M, then measures 5M. The baseline trains Stride’s PC history during demand-only cache warmup and enables issue at ROI entry. These short intervals describe the specified recordings. [Official trace collection](https://github.com/CMU-SAFARI/DPC4#workload-traces) · [Original SPECspeed trace archive](https://dpc3.compas.cs.stonybrook.edu/champsim-traces/speccpu/)

## Reproduction

- Run the commands below from the opportunity_study directory. The parent project’s simulator must be built first. The preparation script reuses the original cached MCF-994 archive and the existing LBM-3766 uncompressed prefix. The public graph inputs are bfs-3.trace.gz and bfs-8.trace.gz. If the local SPEC inputs are unavailable, the preparation script reads the needed prefixes from the official DPC4 collection. For each newly extracted file the script validates the standard 64-byte trace layout at four separated 4,096-instruction samples. Manual, compiled and publicly captured inputs each have separate provenance. [Simulator settings](../../sim/README.md) · [Acquisition](real_traces.py)
- The generated traces record controllable instruction and memory sequences. Their offline source-role labels are stored separately from the policy inputs. Normal generated cases warm on 2,048 loads and measure exactly 8,192. The capacity controls warm on 98,304 loads and measure 196,608. Each runs with identical data addresses and per-core ROI under both policies. The PC, MLP, spacing and mixed-placement controls were checked for identical virtual-to-physical mappings where appropriate.
- A name-selected hosted recording proves little about phase coverage by itself. The split and selection are visible in the registration. Each generated case includes chronological first-half and second-half labels for within-run diagnostics and the held-out variants retain their separate case labels.

```sh
python3 -B workloads/real_traces.py
python3 -B workloads/generate_controls.py
python3 -m pip install --target raw/tools -r workloads/requirements-tracer.txt
python3 -B workloads/record_compiled.py
python3 -B workloads/run.py --jobs 6
python3 -B workloads/summarize.py --jobs 4
python3 -B workloads/check_context.py
```
