# Workloads registered before measurement

- Keep every case below, including cases with few LLC requests or a short useful lead. Use per-load labels from the generator only for retrospective analysis. Feed each policy identical trace PCs, instruction order, operands and physical placement. Reuse the two-core, one-channel, 4 MiB LLC machine and original NoPF and Stride binary. Run single programs with the peer idle. Repeat both policies on every case.
- Develop on the earlier half of each synthetic measured window and test frozen choices on the later half. Keep the entire held-out named variant untouched when selecting history lengths, thresholds or candidate encodings on related development cases. Treat a second segment of the same program as temporal transfer; it is not evidence of unseen-program generalization.
- Vary row length independently of base pitch, comparing alternating 8/24 rows to a longer five-row schedule of 8/20/12/24/16. The latter is a held-out schedule. Test whether longer context retains earlier row run lengths. A held-out previous-row-driven control repeats the preceding row length within a pair with an irregular, deterministic random choice of the next pair length. An independent-row control uses a fresh choice each row; its upcoming boundary is harder to identify from earlier rows.
- Keep the same address streams while changing issue PC: two interleaved streams under one static load versus under two distinct loads. In a separate cross-PC control vary the same target load's destination according to a cue encoded by the PC of a preceding load, with a pseudorandom cue/target relationship across trials. Compare a control with the cue PC masked and the target stream unchanged. If the cue is filtered before the LLC, report the loss.
- Compare a short motif interspersed with unrelated loads, a cyclic phase switch between two strides, and a steady control. Introduce compute-dependent spacing and independent memory chains as separate controls for available lead and overlap. Vary a working set across the last-level capacity and shift an otherwise identical 16-line row pair by 32 lines to change whether the second row crosses a 4 KiB page. The point of the page pair is the matched second row. Compare each crossing condition under both policies.
- Use programmatically generated ChampSim records to control timing and known addresses. Separately compile a small freestanding C nested-row kernel, collect its executed x86 instructions and dynamic memory operands under emulation, and replay this trace on the same timing model. Label these origins separately.
- Use the first 1M instructions for warmup and next 2M for measurement on public GAP BFS-3 (development) and BFS-8 (held-out recording). A new paired BFS-8 + LBM-3766 run tests competition with an unrelated stream under identical IDs; use an LBM-3766 solo over the same 1M+2M interval with its mixed physical slot for comparison. Different recording names do not establish different input graphs or different programs. The adjacency test uses MCF-994, measurements 15M–20M, 10M warmup beginning at 5M, versus the prior independent run measuring 10M–15M. Choose these names before reading results. If the GAP format does not validate, report why, and substitute public 620.omnetpp_s-141B and -874B in the same splits and windows.
- For each case report measured LLC ingress and lookups; matched NoPF miss to Stride LLC hit and confirmed first use; late merges; same and changed misses; exposure and fixed-work cycles. For generator cases also report exact event counts and hits by known category. Show per-core and makespan outcomes for mixed workloads. Evaluate strong rules and history models on separate evidence.
