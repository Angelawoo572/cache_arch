\section{Question}
Holding the existing h8/h16 model, training recipe, fixed evaluation stream,
offline causal inference, keyed replay transport, ChampSim configuration,
measurement window, and metric definitions constant, what is the smallest
trace-start training prefix whose offline keyed-replay system result is
equivalent to the corresponding 20M model? Every h8 point is compared with
h8--20M; every h16 point is compared with h16--20M.
\section{Original 602 offline keyed-replay protocol}
Training uses trace start through $N$ retired instructions with zero training
warmup. Python performs causal offline inference on one fixed held-out stream
and writes one PC--line--occurrence-keyed action list per model. The same
list-replayer binary then runs 25M ChampSim warmup instructions and 25M
measured instructions. Conventional Stride supplies labels only. PC and
cache-line address are the only external neural inputs.
\section{What is fixed and what changes}
Only $N$ changes within an h8 or h16 curve. Seed 7, 12 epochs, TBPTT length
256, PC batch size 128, Adam, learning rate 0.002, runtime encoder, dynamic
exact-PC state routing, hurdle/count/delta heads, prefix-derived class balance,
evaluation stream, replay format, references, cache configuration, and metric
parser remain fixed. Fixed epochs mean larger prefixes receive more optimizer
steps; this measures trace and training work under the current fixed recipe
and does not isolate unique-data diversity from optimizer-step count.

\section{System-performance versus policy-behavior equivalence}
``Reaching at least'' is the one-sided test $IPC_N\ge f\,IPC_{20M}$.
``Within'' is the two-sided test
$\lvert IPC_N-IPC_{20M}\rvert/IPC_{20M}\le\epsilon$. A stable 0.5\%-IPC
plateau requires a candidate and every subsequent observed budget through 20M
to remain within the band. Coverage, miss rate, request pressure, student act
rate, timeliness, and replay-action count are reported separately. The phrase
\emph{policy equivalent} is reserved for evidence that traffic and action
behavior are also close.

\section{Secondary live-deployment validation}
Live results are secondary. They are functional frozen C++ inference in the
ChampSim callback with no replay list, teacher, optimizer, gradient, or weight
update and with \textbf{zero modeled NN inference latency}. The primary four
validation points are h8/h16 at i1m and i20m; h8--i250k and h16--i100k are
additional aggressive candidates. For each point, analysis separately reports
live-$N$ versus offline-$N$, and live-$N$ versus same-H live-20M. Missing
live points are neither interpolated nor used for the primary offline claim.
