\section{Question}
Holding the existing h8/h16 model, fixed training recipe, held-out evaluation
stream, Python offline causal inference, keyed replay transport, ChampSim
binary/configuration, measurement window, and metric definitions constant,
what is the smallest trace-start training prefix $N$ whose offline keyed-replay
system result is equivalent to the corresponding 20M model?

The primary comparisons are strictly
\[
\text{h8-}N\ \text{versus h8-i20m},\qquad
\text{h16-}N\ \text{versus h16-i20m}.
\]
No cross-hidden-size reference is used to decide training-size sufficiency.

\section{Original 602 offline keyed-replay protocol}
The unchanged authority is
\texttt{formal\_NN\_training/experiments/602\_offline\_lstm\_stride/}.
Training uses the trace start from 0 to 20M retired instructions with zero
training warmup. Evaluation is one fixed held-out stream collected with 25M
warmup and 25M measured instructions. Python performs causal offline inference
and writes one keyed replay list per model. The same list-replayer ChampSim
binary/configuration and the same no-prefetch reference measure every point.
Teacher actions are labels only; the only external NN inputs are PC and
cache-line address.

\section{What is fixed and what changes}
Only the trace-start training prefix changes. Hidden size is analyzed as two
predeclared curves rather than as a changing control within a curve. Seed,
model revision, runtime encoder, PC-keyed state router, 12 epochs, TBPTT length
256, PC batch size 128, Adam, learning rate 0.002, Stride teacher, class-balance
formula, evaluation stream, inference semantics, replay format, simulator,
references, and metric parser remain fixed.

Class weights are recomputed from each prefix's own labels:
\[
w_c=\frac{N_{\mathrm{decision}}}{2N_c}.
\]
The 20M label frequencies are never reused for a smaller prefix. Since epochs
remain fixed, larger datasets receive more optimizer steps. This experiment
therefore answers how much trace and training work are needed under the current
fixed recipe; it does not isolate unique-data diversity from optimizer-step
count.

``Reaching at least'' is a one-sided performance-sufficiency test and can
include a point above 20M. ``Within'' is two-sided IPC closeness. A stable
0.5\%-IPC plateau requires the candidate and every subsequent observed larger
budget through 20M to remain within the band. Close IPC/cache outcomes may be
called \emph{system-performance equivalent}. The stronger term
\emph{policy equivalent} is not used unless act rate, request pressure, replay
actions, and action behavior are also explicitly close.

\section{Secondary live-deployment validation}
Offline training means weights are learned before simulation. Offline keyed
replay means Python precomputes actions and ChampSim replays them. Functional
live inference means frozen C++ inference executes inside the ChampSim
callback, with no replay list, teacher, optimizer, gradient, or weight update.
Current live results use \textbf{zero modeled NN inference latency}. A future
latency-aware experiment would explicitly model inference cycles before
issuing requests. Host wall-clock nanoseconds are not simulated CPU latency.

\section{Future latency-aware evaluation}
No simulated NN latency is added in this task. Representative future latency
candidates are h8-i1m, h8-i20m, h16-i1m, h16-i20m, h8-i250k, and h16-i100k.
They should be swept only in a separately named latency-aware experiment.
