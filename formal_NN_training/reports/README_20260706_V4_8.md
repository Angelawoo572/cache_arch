# README — V4.8 Independent Trace-Specialized Neural Prefetchers

**Notebook:** `v4_8_independent_trace_prefetcher_A100.ipynb`  
**Scope:** five independent trace-specialized NN prefetcher pipelines on one A100 GPU.  
**Status:** this document defines an experiment and its acceptance criteria. It does **not** claim that V4.8 beats any normal prefetcher before keyed ChampSim replay.

## 1. Research question and methodological rule

V4.8 distinguishes three separate questions that earlier notebooks sometimes mixed:

1. **Representation / route:** does the candidate bank contain useful future actions?
2. **Ranking and policy:** can the trace-local NN rank those actions and issue them early enough without harmful traffic?
3. **Capacity:** after a route is fixed, how small can the NN become without materially changing replay behavior?

This follows the lecture principle that sufficient capacity is necessary for a network to represent a target function, but an architecture that omits a necessary input/action cannot recover it merely by adding width. Training loss is empirical risk, whereas replay IPC/misses/resources are the system objective. Therefore V4.8 changes candidate representation only in explicitly named route comparisons, selects the route by keyed replay, and only then reduces neural widths.

## 3. Global V4.8 flow

```text
fixed trace + fixed normal reference (evaluation only)
  -> no-prefetch demand/oracle rows
  -> chronological train-prefix / validation suffix split
  -> train-prefix profiling (never validation/future replay)
  -> route-specific candidate sources, merged into exactly 64 slots
  -> trace-local causal feature tensor + trace-local NN class
  -> utility / lead / cycle / far / issue heads
  -> validation policy and resource gate sweep
  -> ordered dedup / optional high-confidence fallback export
  -> per-trace rich list + full decision ledger + storage inventory
  -> keyed ChampSim replay
  -> IPC, misses, accuracy, coverage, timeliness, PQ/MSHR, accepted/rejected/duplicate evidence
  -> route decision or fixed-route width-only Pareto decision
```

## 4. Independence contract

This is one notebook for organization, **not one universal model**.

Every trace has its own class, feature preparation call, raw table, train/validation split object, candidate bank, labels, NN weights, optimizer, scheduler, checkpoint, policy sweep, decision ledger, artifact directory, replay plan, and results tables. No tensor, optimizer state, candidate data, rich list, or artifact path is shared across traces.

The one-A100 default is sequential because it is reproducible and avoids GPU out-of-memory failures. `V48_PARALLEL_WORKERS>1` is controlled job sharding for separate Colab sessions, not unsafe concurrent full-model training inside one GPU process. Each worker owns a disjoint `job_id % workers` set and non-overlapping artifact paths.

## 5. Architecture and storage accounting

Every instantiated model reports:

- trainable NN parameters, calculated by `sum(p.numel() for p in model.parameters() if p.requires_grad)`;
- layer count, layer dimensions, embedding/hidden/state dimensions;
- candidate-bank slots and candidate-source profile/table bytes;
- exported prefetch list rows and bytes;
- non-neural deployment storage: hash-table/profile bytes, policy metadata, dedup capacity, and replay-list bytes.

The main width-only ladder retains hash bucket cardinalities, candidate bank, features, labels, loss, and policy. Hence its minimum feasible rung is bounded by embedding-table storage; a sub-1000 model would require changing/tieing hash tables and is therefore an explicitly separate diagnostic, excluded from the main acceptance ladder.

## 6. Trace-specific design rationale and flowcharts

### 602.gcc_s-734B — coverage residual

Evidence before V4.8: V4.7’s high-accuracy, timely assoc route still trails sandbox because sandbox covers additional timely misses; timing is not the primary loss channel.

```text
no-prefetch 602 oracle
  -> causal V31/association candidate bank (64 slots, baseline)
  -> [route comparison] add profiled_pc_stride slots learned from train prefix
       profile: hot PC -> signed dominant deltas -> support/stability filtered top-K
  -> assoc_coverage LSTM2
       raw causal PC/page/line/history/dependency features + candidate delta/source features
       utility, lead, cycle, far, issue heads
  -> validation policy: NN-only / profiled-bank / hybrid fallback
       hybrid only when NN emits no action at a trigger and profile confidence passes threshold
  -> LRU/dedup + max fallback budget
  -> replay against sandbox: normal-only timely gap, miss delta, pollution/PQ/MSHR
  -> decision: candidate recall vs ranking vs harmful fallback
```

### 605.mcf_s-994B — frozen Stage-B dependency + fixed next-line route

Evidence before V4.8: candidate absence was dominant; V4.7 support16+fixed-nextline improves over AMPM. V4.8 does **not redesign** it before Stage B.

```text
no-prefetch 605 oracle + dependency profile
  -> fixed 64-slot support16 + fixed next-line bank
  -> dependency_fusion LSTM2 (same frozen feature/bank/label/loss/policy route)
  -> full / ~911K / ~383K / feasible ~153K width-only rungs
  -> fixed V4.7 policy (threshold=.50, degree=1, min lead=4, cycle=0, LRU256)
  -> replay gates vs fresh full reference
  -> accept smallest model only if IPC/accuracy/coverage/timeliness/resources survive
```

### 619.lbm_s-4268B — timing, degree, and duplicate pressure

Evidence before V4.8: candidate absence is low; lead/timing/degree selection and duplicate traffic determine behavior. V4.8 keeps lead8 as the anchor, measures cycle0 versus cycle64 under multiple seeds, and compares degree 2/3/4 plus a train-prefix adaptive degree table.

```text
no-prefetch 619 oracle
  -> V31 direct 64-slot bank (unchanged)
  -> timing LSTM2
  -> three independent seeds
  -> fixed lead8 + controlled {cycle64, cycle0} x {top2,top3,top4,adaptive-degree}
  -> dedup/no-dedup semantics recorded
  -> replay against SMS: SMS-only -> NN timely conversion; duplicates, pollution, PQ/MSHR
  -> choose replay mean/variance-aware full route before any width sweep
```

### 620.omnetpp_s-874B — candidate-bank blind spots and conservative expansion

Evidence before V4.8: high PC diversity, substantial candidate absence, strong timeliness once selected, and resource headroom relative to SMS.

```text
no-prefetch 620 oracle
  -> region-pair/residual-pair baseline 64 slots
  -> [route comparison] add train-prefix profiled_pc_stride signed-delta slots
       supports negative/non-power-of-two deltas; no hardcoded PC/delta
  -> region_pair LSTM2
  -> conservative degree {1,2,3} / issue-budget policy sweep
  -> optional high-confidence fallback only after resource guard
  -> replay: absent vs rank/policy/late/harmful diagnosis; SMS-only coverage gap
  -> freeze best replay route then width-only sweep
```

### 623.xalancbmk_s-700B — frozen Stage-B context route

Evidence before V4.8: context route consistently exceeds SPP; dedup/LRU suppression is large but mostly redundant rather than harmful.

```text
no-prefetch 623 oracle
  -> frozen V4.7 context 64-slot bank
  -> context LSTM2 (same feature/bank/label/loss/policy route)
  -> full / ~911K / ~383K / feasible ~153K width-only rungs
  -> fixed V4.7 LRU128 policy (threshold=.65, degree=1, min lead=4, cycle=0)
  -> replay gates versus fresh full context route and SPP
  -> choose smallest accepted model; report total non-neural storage separately
```

## 7. Fairness rules

Within a trace’s architecture/route comparison, all candidates use the same chronological split, oracle labels, export format, replay method, evaluation window, full V4.0 parameter rung, and policy-search mechanics. A bank/source modification is explicitly labeled as a **route** difference. It is never hidden as a NN-size difference.

During width-only Stage B, the chosen route is frozen: architecture family, input features, labels, candidate sources, candidate-bank logic, loss, policy mechanism, lead/cycle/dedup logic, and export format remain unchanged. Only embedding/continuous/hidden widths are changed.

## 8. Acceptance gates after keyed replay

For each smaller candidate relative to the selected full route:

- replay IPC >= 99.5% of selected full IPC;
- selected accuracy >= 95% of selected full;
- event coverage >= 95% of selected full;
- timeliness >= 95% of selected full;
- issue rate <= 110% of selected full;
- PQ/MSHR p95 <= 110% of selected full;
- reject and duplicate fractions may not worsen by more than 0.05 absolute.

The postprocess script writes every gate and exact failed gate list. Exceeding the current best normal is a separate replay-backed report, not a requirement for width retention.

## 11. Limitations

- Offline loss/accuracy is not replay IPC. Keyed replay remains authoritative.
- Trace PCs cannot be mapped to benchmark assembly without a matching PC address space.
- Event evidence is L2C demand-event evidence, not a full causal proof of all microarchitectural effects.
- Exported rich-list storage is not a deployable online predictor implementation; it is measured separately so NN parameters are never confused with total storage.
- `profiled_pc_stride` tables are built from the training prefix only; they are general but still need replay validation for pollution and resource behavior.
